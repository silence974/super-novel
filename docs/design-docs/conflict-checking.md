# Conflict Checking

## 目的

定义手动检查、增量检查、分级冲突、标红定位和修复建议机制。

## 检查模式

### 手动检查

用户主动触发，可选择：

- 检查当前章节。
- 检查当前角色。
- 检查当前事件链。
- 检查全作品。

### 增量检查

由数据变化触发，但仍应让用户感知结果。

触发来源：

- 正文修改。
- 事件确认。
- 状态修改。
- 关系修改。
- 时间域配置修改。
- 修复补丁应用。

## 严重级别

### error

强约束冲突，必须红色标注。

### warning

可能导致设定不稳，需要用户关注。

### notice

信息提示，不影响继续写作。

## 检查结果结构

每条检查结果必须包含：

- `severity`
- `rule_id`
- `message`
- `entity_refs`
- `event_refs`
- `chapter_refs`
- `text_ranges`
- `suggested_repairs`
- `status`

## 影响范围计算

增量检查需要基于变更对象计算影响范围。

示例：

- 修改角色位置事件：检查该角色后续位置链、相关章节、同时间地点冲突。
- 修改道具持有关系：检查道具所有后续持有链和使用事件。
- 修改时间域流速：检查该时间域内所有事件的映射结果。

## 当前 Spike 结论

`spikes/tauri-minimal` 已验证一个最小增量检查流程：

1. 用户变更事实 `fact-lin-town`。
2. 系统计算受影响实体、事件、章节、事实和规则。
3. 系统只运行 `state.location.exclusive` 相关检查。
4. 系统在 SQLite savepoint 中预览修复补丁。
5. 补丁修复位置冲突后，相关冲突从 1 个变为 0 个。
6. 不相关的道具持有冲突仍保留在全局检查结果中。
7. savepoint 回滚，补丁不静默写入数据库。

该流程支持后续产品中的“一键修复但按类型授权”设计。

`spikes/tauri-minimal` 还验证了时间域配置变更的最小影响范围：

1. 用户变更 `Mirror Realm` 到 `Prime World` 的时间流速规则时，系统可先定位该时间域内确认事件。
2. 系统可将本地 domain tick 映射为 canonical world tick。
3. 系统可返回受影响 canonical world tick 范围，例如 `1010 -> 1030`。

该流程尚未接入完整冲突重算；后续需要把时间配置变更纳入统一增量检查队列。

## 标红规则

- 章节树显示最高严重级别。
- 正文内按具体文本范围标红。
- 没有文本范围时，标记章节或事件卡片。
- 检查面板必须展示问题来源和修复入口。

## 修复建议

修复建议可以包括：

- 移动事件时间。
- 修改事件地点。
- 补充过渡事件。
- 修改道具持有人。
- 修改正文描述。
- 标记事件为回忆或梦境。

## 状态流转

```text
open -> acknowledged -> repair_generated -> partially_applied -> resolved -> ignored
```
