# AI Assisted Writing And Review Spec

## 目的

定义 AI 辅助写作、事实抽取、冲突解释和修复补丁生成的用户可见行为。

## AI 使用原则

- AI 是可选工具。
- 用户手动触发。
- AI 输出默认是候选。
- 用户确认后才能入库。
- AI 不自动连续执行完整创作流程。

## 首期 AI 能力

- 生成作品大纲。
- 生成分章大纲。
- 生成正文。
- 润色正文。
- 重写正文。
- 抽取候选事实。
- 解释冲突检查结果。
- 生成修复补丁。
- 生成 embedding 用于语义检索。

## OpenAI API 配置

用户需要配置 API key。

系统必须：

- 不在前端明文暴露 API key。
- 不把 API key 写入项目导出。
- 支持后续 Provider Adapter 扩展。

当前 Spike 结论：

- 已验证 OpenAI Provider Adapter 的最小前后端边界。
- 验证台只展示 API key 是否已配置，不展示 key 内容。
- Provider 返回默认仍为候选态，不直接覆盖正文或写入正式事实库。
- 真实 OpenAI API 调用、模型配置、streaming 和响应解析仍待实现。

## 候选事实确认流

1. 用户触发抽取。
2. AI 返回候选事实。
3. 系统展示来源文本和涉及实体。
4. 用户逐条确认、修改或拒绝。
5. 确认后写入正式事实库。
6. 系统触发增量检查。

## 修复补丁流

1. 用户选择冲突。
2. AI 生成补丁。
3. 系统按类型拆分补丁。
4. 用户分别授权。
5. 系统应用被授权补丁。
6. 系统记录版本并触发增量检查。

## 验收标准

- AI 生成内容不会直接覆盖正式内容。
- 候选事实必须可追溯来源。
- 修复补丁必须可预览。
- 用户可以只应用部分补丁。
